* What this is                                                      :ignore:

Self-contained package for the StarPU tutorial: a one-day, three-session
introduction to the task-based parallel programming paradigm using the
StarPU runtime. Session 1 is a lecture on the concepts and the StarPU
model; Sessions 2 and 3 are guided hands-on labs, each with a student
handout, exercise skeletons, and reference solutions. Everything a
participant or instructor needs for the day is under this directory.

* Sessions overview

The tutorial runs as three sessions in a single day, with a coffee
break between Sessions 1 and 2 and a lunch break between Sessions 2 and
3. An optional buffer slot follows Session 3 for unfinished exercises or
Q&A, used only if needed.

| Session                    | Time        | Duration | Format          | Summary                                                                                                                                                                              |
|----------------------------+-------------+----------+-----------------+--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| [[file:session1/slides.org][Session 1 — Foundations]]    | 09:00–10:30 | 90 min   | Lecture         | The task-based paradigm, DAGs of tasks/data/dependencies, and the StarPU runtime model: the STF execution model, workers, codelets, data handles, and a scheduling overview.         |
| [[file:session2/handout.org][Session 2 — First programs]] | 11:00–13:00 | 120 min  | Guided hands-on | Environment setup (Docker/Podman); three progressively richer StarPU programs (sequential → task-based → data-partitioned); a block-matrix-addition exercise with data partitioning. |
| [[file:session3/handout.org][Session 3 — Heterogeneity]]  | 14:30–16:00 | 90 min   | Guided hands-on | CPU/GPU heterogeneity via multi-implementation codelets, with an instructor-led CPU-vs-GPU demo; recording and visualizing execution traces with StarVZ.                             |

By the end of the day, participants will have written and run their own
StarPU programs on CPU, understood how StarPU infers task dependencies
and parallelism from data accesses, seen how the same codelet structure
extends to GPU execution, and used execution traces to see what the
runtime actually did rather than just measuring wall-clock time.

* Building the slides

Session 1's =slides.org= is a Beamer deck, so it must be exported with
=org-beamer-export-to-latex=, not the plain =org-latex-export-to-latex=
— the latter silently degrades a beamer class file to
=\section=/=\subsection= instead of =\begin{frame}=, with no error, so
double-check frame count if you re-export. Requires =(require
'ox-beamer)= to be loaded first if it isn't already part of your Emacs
config:

#+begin_src bash
emacs -batch -l ~/.emacs.d/init.el \
  --eval "(require 'ox-beamer)" \
  --eval "(setq enable-local-eval t)" \
  --eval "(setq enable-local-variables t)" \
  slides.org --funcall org-beamer-export-to-latex
pdflatex -interaction=nonstopmode slides.tex
pdflatex -interaction=nonstopmode slides.tex   # second pass for cross-references
#+end_src

Needs the =metropolis= Beamer theme (part of most complete TeX Live
installs) and produces some harmless warnings (older-format included PDFs
reporting a missing "ProcSets" resource; one overfull vbox) — no code
listings are used in this deck, so =listing_options.tex= is not needed
here.

* Building the code

Every code subdirectory under =session2/code/= and =session3/code/= has
its own =Makefile=; =cd= into it and run =make=. All of them assume
=pkg-config= can find =starpu-1.4= (true inside the tutorial Docker/
Podman image — see =session2/handout.org= for how to start it *and* for
why the mounted paths appear as =mount/...= inside the container even
though they are =code/...= on the host), except =session3/code/demo/=,
which additionally needs a CUDA toolkit and is meant to be built on the
instructor's GPU machine, not by participants.
