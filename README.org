* Preparing the machines

** Images

Both are pulled once, before the session (about 8 GB and 4 GB):

#+begin_src bash
podman pull registry.gitlab.inria.fr/starpu/starpu-docker/starpu:latest
podman pull docker.io/viniciusvgp/starvz:latest
#+end_src

Tested with the =latest= StarPU image of 2026-08-19 (StarPU 1.4.12,
built with CUDA, OpenCL and FxT; digest
=sha256:4d7355351ed4ac5f8f0eb3129f434ca601f606c1688699906492f0a937419763=)
and the StarVZ image of 2026-09-19 (StarVZ 0.8.4).

To install them on machines without network access, save them once and
load them from a disk:

#+begin_src bash
podman save registry.gitlab.inria.fr/starpu/starpu-docker/starpu:latest | zstd -T0 -19 -o starpu-image.tar.zst
podman save docker.io/viniciusvgp/starvz:latest | zstd -T0 -19 -o starvz-image.tar.zst
zstd -dc starpu-image.tar.zst | podman load     # on each machine
zstd -dc starvz-image.tar.zst | podman load
#+end_src

** Instructor's machine (GPU demo)

Podman sees an NVIDIA GPU through the CDI specification, generated once:

#+begin_src bash
sudo nvidia-ctk cdi generate --output=/etc/cdi/nvidia.yaml
nvidia-ctk cdi list     # must list nvidia.com/gpu=all
#+end_src

The cuBLAS of the image predates the GPU, so the CUDA driver compiles
its kernels at the first CUDA run of a container: about 85 s during
which the program seems stuck. The demo command of the handout keeps
this cache (=~/.nv=) and the StarPU calibration (=~/.starpu=) in two
named volumes, =starpu-nvcache= and =starpu-calib=: run the demo once
before the session, and later runs, even in new containers, start in a
second.

* Building the slides

The slides are a Beamer deck: export them with
=org-beamer-export-to-latex=, not the plain LaTeX export. They need the
=metropolis= theme.

#+begin_src bash
cd slides
emacs -batch -l ~/.emacs.d/init.el \
  --eval "(require 'ox-beamer)" \
  --eval "(setq enable-local-eval t)" \
  --eval "(setq enable-local-variables t)" \
  slides.org --funcall org-beamer-export-to-latex
pdflatex -interaction=nonstopmode slides.tex
pdflatex -interaction=nonstopmode slides.tex
#+end_src

* Regenerating the traces

performance cores, =STARPU_WORKERS_CPUID="0 2 4 6 8 10"=); the GPU traces
from the same laptop with its NVIDIA RTX A1000. To record new ones,
follow Hands-on 3 of the handout, then copy the =.parquet= files of each
trace directory here.
