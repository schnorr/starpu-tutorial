* What this is                                                      :ignore:

Self-contained delivery package for the StarPU tutorial: Session 1
lecture slides, and Sessions 2-3 student handouts with their exercise
skeletons and reference solutions. Generated from the working
repository this directory lives in — see =../roteiro-minicurso.org= for
the full-day schedule, logistics decisions, and the rationale behind
every choice made here (why Docker/Podman and not Spack, why CPU-only
exercises plus an instructor GPU demo, why the simple example was
chosen over the official GEMM for the heterogeneity demo, etc.).

This package intentionally does *not* copy the entire working
repository — only what a participant or instructor needs on the day.
A few handout notes point back at the full repository (e.g. the
official =starpu-docker/tutorial/C/gemm/= example) for optional,
after-the-tutorial reading.

* Building the slides

Session 1's =slides.org= is a Beamer deck, not a plain article like the
rest of the project — it must be exported with
=org-beamer-export-to-latex= (not the plain =org-latex-export-to-latex=
used by =capitulo/Makefile=; the latter silently degrades a beamer
class file to =\section=/=\subsection= instead of =\begin{frame}=, with
no error, so double-check frame count if you re-export). Requires
=(require 'ox-beamer)= to be loaded first if it isn't already part of
your Emacs config:

#+begin_src bash
emacs -batch -l ~/.emacs.d/init.el \
  --eval "(require 'ox-beamer)" \
  --eval "(setq enable-local-eval t)" \
  --eval "(setq enable-local-variables t)" \
  slides.org --funcall org-beamer-export-to-latex
pdflatex -interaction=nonstopmode slides.tex
pdflatex -interaction=nonstopmode slides.tex   # second pass for cross-references
#+end_src

Needs the =metropolis= Beamer theme (already on this machine's TeX Live)
and produces some harmless warnings (older-format included PDFs
reporting a missing "ProcSets" resource; one overfull vbox) — no code
listings are used in this deck, so =listing_options.tex= is not needed
here.

* Building the code

Every code subdirectory under =session2/code/= and =session3/code/= has
its own =Makefile=; =cd= into it and run =make=. All of them assume
=pkg-config= can find =starpu-1.4= (true inside the tutorial Docker/
Podman image — see =session2/handout.org= for how to start it *and* for
why the mounted paths appear as =mount/...= inside the container even
though they are =code/...= on the host), except =session3/code/demo/=,
which additionally needs a CUDA toolkit and is meant to be built on the
instructor's GPU machine, not by participants.
